# Documentation Rules

## Context
You are writing or updating documentation for this AI enterprise.

## Placement by Type
| Content | Directory |
|---|---|
| Architecture decisions | `framework/` |
| Operational processes | `process/` |
| Agent profiles | `agents/` |
| Community / outreach | `community/` |
| Roadmap / planning | `to implement/` |
| Brainstorming outputs | `brainstorming/` |

## File Rules
- Every new service, agent, or system gets its own `.md` file
- Filenames: lowercase, underscores, descriptive (e.g., `payment_gateway_service.md`)
- Every `.md` must include: purpose, owner agent, status (draft/active/deprecated)

## Brainstorming Outputs
All brainstorming sessions must be saved before any code is written. Commit the `.md` first.

## When Done
→ File committed to the correct directory  
→ STOP — no further action unless instructed
