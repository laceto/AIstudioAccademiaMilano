## Part 3 — How to Get Better: Improvement Analysis

### 🔴 P1 — Critical (fix before next request)

#### 1. Pricing table must be pre-populated, not learned reactively
**What happened:** Marco charged €1.90 for an invoice that should cost €3.90. Revenue lost on every first-occurrence product type.

**Why it’s a problem:** The learning loop only adds prices *after* a mistake. For a real dispenser, that’s real money lost.

**Fix:**
```json
// config/global_settings.json — add upfront
"pricing": {
  "static_landing_page":  "€9.90",
  "pdf_document":         "€1.90",
  "invoice_pdf":          "€3.90",
  "logo_design":          "€14.90",
  "email_delivery":       "€0.50",  // add-on
  "unknown_product":      null      // block until Luigi sets price
}
```
Marco should **block delivery** if product type has no price, not use a fallback.

---

#### 2. `intent_to_skill_map` must cover all intent variants before going live
**What happened:** Gianni spent 3s manually resolving `invoice_generation` because it wasn’t mapped. This is wasted time and a failure mode if Gianni gets it wrong.

**Why it’s a problem:** Manual resolution by Gianni is not deterministic — different prompts could produce different stacks.

**Fix:** Before going live with any new intent, run a mapping session:
```yaml
# process/intent_registry.yaml
invoice_generation:
  skills: [fpdf2_pdf_generation, invoice_template_pdf]
  delivery_options: [email, download]
  requires_auth: [gmail_api_oauth]  # if email
business_card:
  skills: [image_generation, pdf_generation]
  delivery_options: [print, download]
qr_code:
  skills: [qrcode_generation]
  delivery_options: [print, download, url]
```
Stacy reads this file directly — Gianni only intervenes for unknown intents.

### 🟡 P2 — Important (schedule soon)

#### 3. OAuth prompt breaks the flow for repeat users
**What happened:** Request 002 and 003 both required a full OAuth prompt because the token expires per session.

**Why it’s a problem:** For a physical dispenser, asking the user to authenticate twice in one session is friction. For a kiosk context, it breaks the “< 60 second” promise.

**Fix options:**
- **Option A (simple):** Cache the OAuth token in an encrypted local session store for 60 minutes. Risk score: 3 — Luigi approval needed.
- **Option B (better UX):** Use AI Studio’s own sending address (`noreply@aistudio.it`) by default. Offer Gmail as an opt-in premium feature. No OAuth for 80% of users.
- **Option C (enterprise):** Pre-authorize the dispenser’s own Gmail service account. Users pick the sender from a pre-approved list.

**Recommendation:** Ship Option B now, build Option A in parallel.

#### 4. No template library — Chiara rebuilds every time
**What happened:** Requests 002 and 003 both used `fpdf2` but Chiara wrote the layout from scratch each time. Invoice took 12s; with a template it would take ~3s.

**Fix:** Create `templates/` folder:
```
templates/
  pdf/
    invoice_standard.py    # fpdf2 class, takes dict of fields
    receipt_simple.py
    certificate.py
  html/
    landing_page_warm.html  # warm palette, hero + about + contact
    landing_page_minimal.html
  email/
    delivery_notification.txt
```
Chiara calls `invoice_standard.py(fields=...)` — generation drops from 12s to 2s.

---

#### 5. Pattern threshold of 3 is too high for security-sensitive hooks
**What happened:** `gmail_api_send` is at 2/3 toward promoting a new hook. But the `oauth_dependency_check` hook was correctly promoted at 1 occurrence because it was explicitly added in learning delta 002.

**Why it’s a problem:** Security-critical patterns (OAuth, payment, write APIs) should get hooks faster. Cosmetic patterns (colour palette, font choice) can wait for 5+ occurrences.

**Fix:** Tiered thresholds:
```json
"pattern_thresholds": {
  "security": 1,
  "external_api_write": 2,
  "skill_preload": 3,
  "ui_preference": 5
}
```

### 🟢 P3 — Nice to have (backlog)

#### 6. Audit log is still written manually by Stacy
**Problem:** Stacy has to remember to fill in the YAML block. If she misses a field, the learning loop crashes.
**Fix:** Auto-generate the audit log skeleton from a Pydantic model at session start. Stacy only fills in the values, not the structure.

#### 7. No parallel execution between Chiara and email prep
**Problem:** Chiara generates the PDF (12s) *then* prepares the email (2s) sequentially. These can run in parallel.
**Fix:** Chiara spawns two coroutines: `generate_pdf()` and `prepare_email_draft()`. Total time: max(12, 2) = 12s instead of 14s.

#### 8. Learning loop has no rollback
**Problem:** If `learning_loop.py` writes a bad entry to `global_settings.json` (e.g. wrong intent mapping), there’s no automatic revert.
**Fix:** Before writing, `git stash` the current settings. If the next request fails within 60s, auto-revert with `git stash pop`.

#### 9. No visibility dashboard
**Problem:** Luigi can’t see at a glance: how many requests ran, which skills are hot, which agents are slow, which prices are wrong.
**Fix:** A weekly auto-generated `process/reports/weekly_YYYY-WNN.md` from audit logs. Could be a GitHub Action on schedule.
