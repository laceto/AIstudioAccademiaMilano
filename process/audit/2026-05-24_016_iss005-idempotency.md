## Summary

Two-part fix on `scripts/learning_loop.py` to stop the duplicate-`learn:`-commit spam (~14 commits piled up for request 014 over the last hour):

1. **Idempotency guard.** `settings._meta.last_processed_audit_log` holds the filename of the last audit log we ran against. The loop exits early when it matches the latest log. A new `--force` CLI flag overrides the guard for manually-rerun cases.

2. **No-op commit guard.** `commit_changes()` now checks `git diff --cached --quiet` after staging. Returncode 0 (nothing actually staged-different) → skip `git commit` and `git push`. Belt-and-suspenders against future regressions in the silent mutators.

## Root cause (the part that wasn't obvious)

`changes == 0` from the top-level counter did **not** imply "settings file is unchanged on disk." `update_agent_stats()` recomputes `avg_sec` and bumps `count` on every run, and `check_pattern_hooks()` bumps `pattern_counters[skill]` on every run, both *without* incrementing the `changes` return value. So every Stop event:

1. Read settings
2. Silently mutated counters + averages
3. Wrote settings back (non-empty diff)
4. Committed (because `risk_score < 3` is the only gate)
5. Pushed

Idempotency stops this at step 1.
