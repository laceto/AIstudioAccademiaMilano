## What was built

A CLI that turns one month of a parent's casual WhatsApp "time
capsule" chat (voice notes, photo attachments, short milestone
texts) into a single, beautifully structured Markdown chronicle:
`Niccolo_Age_5_Month_<Month>.md`. Four sections exactly as specified
— The Quote Board, The Art & Creation Catalog, The Development &
Habit Tracker (with a categorised habit table), and A Letter to
Future Niccolò. Single OpenAI gpt-4o call in `json_object` mode,
strict schema validation, deterministic Markdown renderer.

## Why this design

1. **Three-file architecture (parsers / prompts / renderers).** Same
   shape as req 023. The parser owns the messy real-world input
   (two WhatsApp `.txt` line dialects + a CSV shape, multi-line
   messages, attachment dialects on iOS and Android); the renderer
   owns the layout; the LLM only owns the *semantic* sorting and the
   prose. Each layer is independently testable.
2. **No pre-classification before the LLM.** A regex that decides
   "this line is a quote, that line is a milestone" would break on
   the first parent who writes "Niccolò just said..." in their own
   prose rather than literal quotation marks. Letting gpt-4o classify
   directly from the raw message stream is the right tradeoff —
   one call, one cost, zero brittle heuristics.
3. **Validator owns the keepsake invariants.** The renderer rejects
   short letters (< 200 chars), letters containing Markdown
   characters (so the prose always renders as a clean paragraph),
   habit categories outside the allowed 8, and any empty quote /
   review / observation. The model cannot ship a malformed keepsake.
4. **Verbatim quote preservation is in the system prompt as a hard
   rule.** A 5-year-old's grammar is the point — "translating" it to
   adult logic would destroy the artefact's emotional value. The
   prompt instructs the model NOT to clean up the child's phrasing.
5. **ASCII-folded filename.** The child's display name is `Niccolò`
   but the spec asks for `Niccolo_Age_5_Month_[X].md`. NFKD
   normalisation + ASCII-encode-and-strip cleanly removes the
   accent while keeping the in-document name accented (best of both
   worlds — portable filename, real name in the prose).
6. **Vision deliberately deferred.** v1 grounds the artistic review
   in whatever caption the parent typed next to the photo, not in
   the image content. This keeps the default privacy footprint
   small — no media files leave the laptop — and matches the spec's
   "AI-generated artistic review" wording, which does not require
   actually looking at the picture. A `--vision` flag is listed as
   a follow-up.

## Follow-ups (not in scope)

- `--vision` flag to ship actual image files to a vision model so the
  artistic review is grounded in the drawing itself.
- Yearly aggregator: stitch 12 monthly files into one book-shaped
  Markdown / PDF (the "18th birthday gift" the spec hints at).
- `whisper-1` transcription step for raw voice notes (in case the
  parent didn't type out what was said).
- Cron-driven monthly run + email delivery.
- Sibling mode: `--name "Niccolò,Sofia"` → one chat, two chronicles.
