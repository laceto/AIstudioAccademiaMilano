## What was built

A CLI that converts favourite dishes + favourite ingredients + season
into a single `Weekly_Menu_<Season>.md` containing the 7-day
breakfast/dinner matrix (with strict batch-cook pairing) and a
categorised grocery list. Single OpenAI call (json_object mode),
strict schema validation including a structural rollover-rule
invariant, deterministic Markdown renderer.

## Why this design

1. **Validator owns the invariants** — the model is asked to emit a
   "cook" / "leftover" sequence, but the renderer rejects any plan
   that doesn't strictly pair them and forbids a "cook" on Sunday.
   This means the rollover rule is *guaranteed*, not just requested.
   Same pattern as req 021's exactly-7-days check, extended to a
   relational invariant across consecutive days.
2. **Single call, one file** — the user asked for one Markdown file
   covering both sections. Two separate calls would risk grocery-menu
   drift; one call keeps the ingredient list and the menu in lockstep.
3. **Emojis live in the renderer** — keeping them out of the JSON
   contract means the model can't smuggle in extra Markdown or break
   our table layout. The renderer owns the visual shell.
4. **Pattern reuse from req 021** — same architecture (prompts /
   renderers / CLI / tests / dry-run / sample), same JSON-object
   response format, same `--dry-run` ergonomics. New product type, same
   muscle memory.
